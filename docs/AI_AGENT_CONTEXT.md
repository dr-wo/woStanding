# AI Agent Context

This document is the first stop for future AI-assisted changes in `woStanding`.
It summarizes the repository shape, current behavior, and conventions to preserve.

## Purpose

`woStanding` is a small Python package for Formula 1 standings analysis and
visualization. It is intentionally separate from `woStrategy`: standings,
championship tables, season points, and related plots belong here; race
strategy, telemetry, lap-time filtering, tyre degradation, and long-run
analysis belong in `woStrategy`.

The current feature set plots accumulated points by driver and by team for a
season range, including sprint points by default.

## Package Layout

The package follows the same lightweight layering pattern as `woStrategy`:

```text
analysis -> plots -> script
```

- `src/wostanding/analysis/`: pure dataframe transformation and aggregation.
- `src/wostanding/plots/`: matplotlib rendering from analysis results.
- `src/wostanding/script/`: CLI and workflow orchestration, including FastF1 IO.
- `tests/`: focused tests for dataframe calculations and result normalization.
- `docs/assets/`: tracked README images that should render on GitHub.

Keep FastF1 network/session loading out of `analysis`; put it in `script` or a
future IO/tool layer. Keep plotting out of `analysis`; pass structured results
into `plots`.

## Current Entry Point

Run the points progression workflow with:

```bash
python -m wostanding.script.points_progression \
  --year 2026 \
  --race-start 1 \
  --race-end 5
```

By default this:

- Loads FastF1 event schedule with testing excluded.
- Loads race results for each selected round.
- Adds sprint results when the event format contains `sprint`.
- Aggregates race and sprint points by `RoundNumber`, `EventName`, `Driver`,
  and `Team`.
- Calculates cumulative driver and team points.
- Saves driver and team PNGs plus event/driver/team CSV exports under `temp/`.

Use `--exclude-sprints` for race-only points.

## Data Contract

`calculate_points_progression` expects a dataframe with these columns:

```text
RoundNumber, EventName, Driver, Team, Points
```

It returns `PointsProgressionResult`:

- `event_points`: cleaned per-event driver/team point rows.
- `driver_points`: per-round driver points with `CumulativePoints`.
- `team_points`: per-round team points with `CumulativePoints`.

The analysis layer fills missing point values with zero, drops rows without a
driver or team, coerces round numbers to integers, and preserves zero-point
rounds for drivers/teams that appear elsewhere in the selected range.

## Plotting Conventions

`plots/style_maps.py` owns team colors. Use known F1 colors where available and
matplotlib `tab20` fallback colors for unknown teams.

Driver progression uses team color plus driver-specific line style and marker
within each latest team. This is important for legend readability because
teammates share colors.

README example images must be stored inside this repo, currently:

```text
docs/assets/points_progression_2026_drivers.png
docs/assets/points_progression_2026_teams.png
```

Do not point README images at `../temp/...`; GitHub will not reliably render
paths outside the repository.

## Dependencies

Declared runtime dependencies:

- `fastf1`
- `matplotlib`
- `pandas`

The package requires Python `>=3.9` and uses modern type hint syntax.

## Testing And Verification

Preferred checks:

```bash
python3 -m compileall src/wostanding
python3 -m pytest tests
```

Some local environments may not have `pytest` or runtime dependencies
installed. If pytest cannot run, report that explicitly and at least run
`compileall`.

## Change Guidance

- Add standings/championship workflows here, not in `woStrategy`.
- Keep `analysis` deterministic and testable with in-memory dataframes.
- Keep CLI defaults in `SCRIPT_CONFIG`.
- Add tests when aggregation rules, points handling, or result normalization
  changes.
- Prefer small modules matching the existing `analysis`, `plots`, and `script`
  separation.
- Avoid adding generated bytecode caches or temporary CSV/PNG outputs to the
  repo, except intentional README assets under `docs/assets/`.
